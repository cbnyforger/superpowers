## Verdict: not airtight. Findings, strongest first

**1. The envelope can be read as forbidding the fix routes — turning A into sanctioned compliance.** The baseline's actual argument was "installing system packages... belongs to the user." The red-flag rows counter the *scope* half of that, but not the *envelope-classification* half. Exploitable lines (SKILL.md:44-48, 50-52):

> "**No destructive ops outside the worktree.** ... Carve-out: killing zombie dev-server processes / freeing stuck ports is allowed - log it."
> "If <TASK> requires crossing a limit ...: complete everything up to the boundary, log the gap, put the exact crossing command in the final report."

A missing node-gyp header is fixed by mutating the machine outside the worktree (`brew install`, `xcode-select --install`). The envelope explicitly carves out exactly one local-machine mutation (killing zombies), which implies unlisted mutations are forbidden — and the "crossing a limit" paragraph then gives the agent a *skill-blessed* way to stop that item and write the command in the report. That is Option A wearing an envelope costume. Minimal fix, extend the carve-out: "Carve-out: local dev-environment changes needed to build or test - installing system packages/headers/toolchains, killing zombie processes, freeing ports - are allowed; log each."

**2. "The user's invocation text overrides any of this." (SKILL.md:65-66).** This is meant to let users adjust the bar, but it has no explicitness guard. A-shaped exploit: the invocation says "using the approved library `pdfgen`" — so library substitution "contradicts invocation text," collapsing the route list. C-shaped exploit: "expects the feature done" by 9am — an inferred deadline "overrides" both the bar and "No run bounds," so ship the TODO stub. Minimal fix: "The user's *explicit* invocation text overrides these defaults; inferred deadlines, urgency, or preferences do not, and a named tool/library is a default route, not a constraint."

**3. The permission-prompt escape (SKILL.md:32-33).** "permission prompts are the one blocker this skill cannot remove." Several plausible routes here (system installs, `sudo`) are prompt-gated. A pressured agent can generalize: "my remaining routes all hit the one blocker the skill admits it can't remove, therefore the run is legitimately blocked" — Option A with a citation. The skill never says what a mid-run prompt does to the route list. Minimal fix, append: "A prompt blocks a route, never the run - cross off the prompt-gated route and take the next."

**4. The hard-problem protocol has no trigger definition (SKILL.md:110-112).** Step 1 says "Use superpowers:systematic-debugging to find the true cause" — debugging framing. The baseline's opening move was exactly the categorical dodge this permits: "a system-environment problem, not a code problem," i.e. "the protocol governs bugs, not provisioning failures, so it doesn't apply and A is fine." Minimal fix, add a trigger clause to the heading line: "**Hard-problem protocol (never stop)** - applies to ANY blocker: bug, test failure, build/install failure, missing dependency, broken tooling or environment."

**5. Termination vs. protocol step 5 deadlock (SKILL.md:135 vs 118-121).** Termination: "Print 'FINAL' only when: every task meets every bar criterion." Protocol 5: "ship the largest verifiable subset, log the gap." If the list were truly exhausted, these contradict — no FINAL is ever reachable, and a lawyerly agent could resolve the contradiction by stopping to report (A). Minimal fix in Termination: "every task meets every bar criterion - or carries a hard-problem gap whose exhausted route list is in the run log."

**6. Placement risk (easy to miss, not ambiguous).** The counter that actually flipped this scenario — "Retry count is not route count" — lives only in the last row-group of the red-flags table (SKILL.md:162), the final lines of the file, far from the protocol it patches. Under long-context pressure the table is the most droppable part. Minimal fix: duplicate the load-bearing clause into protocol step 2: "ENUMERATE ROUTES: a numbered, best-first list (retries of the same command count as one route)."
